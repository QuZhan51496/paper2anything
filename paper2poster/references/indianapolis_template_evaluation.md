## General Design Rules Extracted

- **Separate title from claim:** The paper title, authors, and affiliation should occupy a stable top title band. The hero claim is a separate band below it.
- **Use row-major reading by default:** For generated posters, prefer left-to-right within a row, then top-to-bottom. Avoid layouts that require the eye to jump between far columns.
- **Reserve figure space before placing text:** Good templates leave explicit graph/image regions. The layout engine should allocate method/result visuals first, then place support text around them.
- **Use section headers as a visual index:** Consistent short headers make the poster scannable. Header styling should be uniform and not oversized inside small cards.
- **Keep references and details secondary:** References, acknowledgments, and contact information belong in compact footer/side regions and should never compete with evidence.
- **Prefer simplified evidence over raw tables:** Dense tables should become metric cards or simplified charts. The full table can remain as a small evidence artifact only when readable.
- **Make one visual hierarchy decision:** A poster should have a main claim and a main evidence region. Equal-weight boxes make generated posters look like dashboards.

## Changes To Apply To Paper2Poster

- Add a `poster_structure` layer before geometry: `title_band`, `hero_claim_band`, `row_1`, `row_2`, optional `footer`.
- Add archetype-specific structures: `benchmark_summary`, `method_flow`, `hero_result`, `visual_demo`, `theory_claim`.
- Add row and column alignment constraints so generated layouts form explicit reading lanes.
- Add a `figure_reserved_space_score` to penalize figures squeezed into corners.
- Add `section_header_consistency_score` and `row_alignment_score` to the VLM/deterministic critic.
- Make the Hero Claim Rewriter produce a complete sentence, while metric cards hold short labels and numbers.
- Treat old decorative styles as negative examples for color/gradient, but positive examples for grid discipline.

## Operational Rubric For Paper2Poster Agents

The template study should become explicit scoring criteria rather than informal inspiration. A generated poster should be rejected or repaired when it fails any of these checks:

| Criterion | What to check | Good pattern from templates | Repair action |
| --- | --- | --- | --- |
| Title separation | Paper title is a real title, not a claim or metric. Authors/venue metadata stay in the title band. | `postertemplate`, `CMS`, `style_e`, `style_f` | Move claim into a hero band; restore paper title from parsed metadata. |
| Hero claim quality | Claim is a complete sentence with a verb and clear research message. | Strong instructional poster examples use a first-sentence takeaway rather than a raw number. | Rewrite headline as sentence; move raw number into a metric card. |
| Reading order | Main sections follow left-to-right within rows, then top-to-bottom. | `style_e`, `style_f`, `CMS` | Repack blocks into row lanes; avoid tall sidebars spanning unrelated rows. |
| Visual reservation | Main result/method figure is allocated before text and receives enough area to be readable. | `style_b`, `style_c`, `13imr-heart` | Enlarge/crop/simplify the figure; move supporting text to smaller blocks. |
| Evidence distillation | Dense tables are converted into 2-4 readable metrics or simplified charts. | Scientific examples emphasize visible evidence, not raw tables. | Run result distillation before layout; create metric cards or a small chart. |
| Section indexing | Headers are short, consistent, and act as visual navigation. | `CMS`, `bluegreen`, `style_f` | Normalize section labels and header styling. |
| Hierarchy | One primary evidence region dominates; secondary blocks support it. | `style_c`, `13imr-heart` | Reduce equal-card dashboard layout; assign primary/support/footer roles. |
| Footer discipline | References, acknowledgments, and links stay visually secondary. | Most UIndy templates reserve compact footer/reference zones. | Shrink references; do not let them compete with results. |
| Style restraint | Avoid dated bevels, heavy gradients, decorative backgrounds, and theme art unless domain-relevant. | Negative examples: `blueBevel`, `children`, `style_m` | Keep flat backgrounds, restrained color, and typography-led hierarchy. |

## Direct Mapping To The Current Pipeline

1. `poster_agents.py`: add or strengthen agents for `Title Normalizer`, `Hero Claim Rewriter`, `Result Distiller`, and `Visual Curator`. Their output should be structured fields, not prose-only advice.
2. `generate_layout.py`: generate `poster_structure` first, then geometry. The structure should select an archetype and reserve title, hero, primary evidence, support text, and footer regions before placing content.
3. `render_poster.py` and `render_preview.py`: render metric cards and simplified result charts as first-class visual elements; avoid treating every section as the same boxed paragraph.
4. `app.py`: add deterministic scores for title separation, complete-sentence hero claim, row-major reading order, figure reserved area, and section header consistency.
5. VLM critique: ask the model to judge the rendered poster against the rubric above and return repair actions in schema form, especially for unreadable figures, weak hierarchy, and broken reading order.
